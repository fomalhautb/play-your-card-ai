# 组件需求单

《正式版架构》第 8 章第 9 条的产物：把黑客松版客户端里所有按钮、边框、面板、弹窗
逐个截图、比对、去重，编成带编号的变体。那份客户端已经随第 38 条删掉，
这份清单和下面这批截图就是它留下的全部记录（源码去版本历史里翻）。
这份清单是 `canvas`（Pixi）和 `ui`（React）两个组件库的需求输入——第 17、28~31 条按场景
逐步实现时，从这里挑变体，不再另起炉灶（7.1 第 1、2 条）。

**这是需求，不是设计定稿。** 旧版怎么长的就怎么记，包括那些明显该合并的重复；
该合并的写在文末「去重记录」里，该补的令牌写在「令牌缺口」里。

**2026-09-12（简化第 3 步）：`ui` 那一半现在全是素方块。** React 组件库的样式整个剥掉了
（颜色、字体、圆角、阴影、动画、图标一样不剩，只留摆位），编号变体也不再有第二档可选。
所以下面每条里「归 ui」的落地记录说的是**剥之前**的样子——那些数值仍然是有效的需求输入，
视觉整套重做时从这里重新挑。

**2026-09-12（简化第 4 步之一）：首页、房间页、开包页这三页在 `canvas` 里也剥成素方块了。**
画布这边立了一个通用原语 `Box`（1px 描边矩形加一行字，见 `canvas/src/components/Box.ts`），
这三页的按钮、面板、文字全换成它；只服务这三页的组件（`PlateButton`、画布版 `SealButton`）
连同它们的底图素材一起删了。对局页、组牌页、选英雄页还没动（简化第 4 步余下三个 PR）。

## 怎么用

- 截图在 `docs/design/inventory/`，文件名是「幕名\_\_元件名[--状态].webp」，
  改名之前先看一眼本文档。**重拍不了了**：拍它们的脚本驱动的是黑客松版界面，
  那套界面和脚本都随第 38 条删掉了，这批图从此只读。
- 桌面档 1440×900 拍元件和整页，手机档 390×844（横屏对局那两幕是 844×390）只拍整页——
  旧版是 1672×941 的死版式整体等比缩放，手机上不是另一套版式而是同一套被缩小，
  需求第 3 条要的「两档并列」在这里恰恰是一条要改掉的现状。
- 状态矩阵的记号：**✓** 已截到 · **✗** 未截到（要凑的局面这次没凑出来）· **—** 不适用。
- 编号按类型各自从 A 排。《正式版架构》7.1 举的例子是「按钮 A、B、C，边框 X、Y、Z」，
  那里的 X/Y/Z 只是说明「变体要编号」，不是要求边框从 X 开始；十类元件各排一套字母更好记。

结论写在这儿，省得每个变体里重复：**旧版整页只有一套版式**，手机档是同一张 16:9 舞台
缩到屏幕里，字号、留白、命中区全跟着缩。正式版这十个界面都要按两档分别排，
本需求单里每个变体的尺寸都只是**桌面档的现状值**，不是要照抄的目标值。

### 按钮 A（墨蓝匾额）

![](inventory/design__plaque-navy.webp)

- **用途**：全站主操作键——确认、开始、结束、离开。
- **出现在**：对局（结束出牌的底座、离开确认弹窗里的取消/确认）、组牌页（确认牌组）、
  选英雄页（确认英雄的底座）、回合结算（确认）、终局结算（再来一局 / 回首页）、
  新手教程（开始教学 / 跳过教程 / 确定 / 取消）。
- **状态**：普通 ✓ · 悬停 ✓ · 按下 ✓ · 禁用 ✓ · 加载 —
  （`design__plaque-navy--hover` / `--press`，禁用是 `design__plaque-navy-disabled`。
  会跳页的那几颗不排「按下」，见去重记录第 6 条。）
- **尺寸和关键值**：默认 224×68，`padding: 0 30px`，24px/600 字、字距 0.25em；
  八角外形由 `clip-path` 切出，不是圆角；底 `#253149`、描边 `#77766f`、内线
  `rgb(174 168 151 / 62%)`、字 `#e7e1d4`；悬停底 `#2c3953`、内线转暖 `rgb(203 157 123 / 85%)`、
  字 `#ead0b9`；按下 `translateY(6px) scaleY(0.96)`，220ms 弹性曲线，最短压入 70ms；
  禁用底 `#676965` 加 `saturate(0.25)`。框线是内联 SVG（三道细线 + 四角折线 + 左右星芒），
  整块套 `#ai-duel-rough-button` 手绘位移滤镜。
- **归属**：**两边都要**。对局、组牌、英雄、教程在 `canvas`；离开确认弹窗是纯文字弹窗，
  归 `ui`。
- **旧组件**：`src/ui/PlaqueButton.tsx` + `styles.css` 的 `.plaque-button`。

## 拿不准的地方

归属规则是「首页、对局、牌组、英雄页、开包、房间页归 `canvas`，信息页、生成页、设置、
账号、弹窗、列表归 `ui`」。下面四处两条规则打架，先按这里的判断填了归属，等做到对应
迁移条目时再定。

1. **终局结算和回合结算算「对局」还是「弹窗」**（面板 H、面板 I、弹窗 E）。
   两层都是纯文字纸面、没有卡牌，按「弹窗归 ui」应当进 `ui`；但它们铺满的是对局那块
   16:9 舞台、和对局共用同一套缩放和纸色变量，按「对局归 canvas」应当进 `canvas`。
   **已定**：两层分开归。回合结算（面板 I、面板 J、面板 K）归 `canvas`——它摆着
   AI 头像卡，卡不能进 DOM（2.1 条），这一层跨不过去。终局结算（面板 H、弹窗 E）归 `ui`——
   《正式版架构》第 8 节第 31 条写明「设置、账号、结算等文字界面用 `ui` 组件库重做」，
   终局结算就是那个「结算」。两层拆到两边的代价是纸色和缩放要各自从令牌取，不再共用变量。
2. **新手引导的挖洞遮罩**（弹窗 D、按钮 O）。它是浮层，按规则该归 `ui`；
   但它要在对局画面上按元素矩形挖洞、描高亮环，而 2.4 条明确说「需要 DOM 元素和画布对象
   对位的设计一律不做」。**已作废（简化第 1 步）**：第 32 条最后选的是「`ui` 画浮层、
   场景按语义锚点回答矩形」那条路，而教程随后整条下线，两个变体都不做了。
3. **加载页**（条 B、条 D）。它出现在每一个界面进场之前，包括对局和牌组这些画布界面。
   **已作废（简化第 2 步）**：加载页换成一行纯文字，两个变体都不做了，归属之争跟着消失。
   那一行字仍然由 React 壳画（`client` 的 `screens/LoadingScreen.tsx`），理由照旧：
   加载的时候画布还没起来。
4. **返回按钮和静音钮标了「两边都要」**（按钮 H、按钮 J，还有图标 A/B/C、边框 A、
   边框 D、面板 A、提示 E）。这不是妥协，是这几个零件确实横跨文字界面和画布界面。
   它们的做法应当是：**同一份设计令牌，两套实现**（`canvas` 一份 Pixi、`ui` 一份 React），
   而不是想办法共用一份代码——7.1 第 1 条说的就是两套组件库各自唯一，不是一套跨两边。

### 本单没列到、随第 31 条（文字界面）一起补的

设置、账号、关于三页动手做的时候又露出三样——本单是照着**旧版**盘点出来的，
而旧版根本没有设置页和账号页，这三样在那边不存在，自然也就不在单子上：

- **设置开关**（`ui` 的 `Toggle`）。一行里左边标题、下面一行小字说明、右边一个滑块，整行可点。
  不是 `<input type="checkbox">`：复选框的方框是浏览器画的，要盖掉它得先 `appearance: none`
  再自己画一遍，到头来和现在一样是「自己画一个」，而按钮天生就有按下语义。
  用 `role="switch"` + `aria-checked`，读屏软件才读成「开 / 关」而不是「选中 / 未选中」。
- **文字页外壳**（`ui` 的 `Page`）。左上角返回、正中标题、右上角一两颗控件、下面一块能滚的正文。
  旧版只有信息页一页用得上这套，所以它是就地写在 `info.css` 里的；三页共用之后提成了组件。
  安全区走 CSS 的 `env(safe-area-inset-*)` 而不是 `platform.safeArea`——
  后者存在是因为画布够不着 CSS，而这一页整个是真 DOM。
- **这两样和 `TextField` 一样还没有编号**。三者都属于「表单和页面骨架」这一类，
  旧版一个都没有，凑齐之后一起编号更省事；现在各自的文件头里写清了它的来历和取值依据。

另外，提示 E（错误红字）在 `ui` 这一半多出了两档语气（成功绿、次级墨色）：
本单只记了红字那一档，而做出设置页和账号页之后，「重置完成」和「这一项暂时没有」
这两句也要有地方说，它们显然不是错误。版式完全一样，所以是同一个组件的三档语气。
