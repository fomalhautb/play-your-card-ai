# @ai-duel/legacy-client

黑客松版客户端，原来叫 `packages/client`。**已经冻结**。

- **不加功能。** 只修会让线上崩掉的问题。新界面、新交互一律做在正式版的 `packages/client` 和 `apps/web` 里。
- **不进 lint。** 这一版是几千行的单文件加一整个全局 css，按正式版的 lint 规则（单文件 400 行、依赖方向、无全局样式）根本过不了，所以直接排除在外。只保留 `typecheck` 和现有的测试。
- **仍然是线上版本。** 部署流水线构建的就是这个包，`packages/server` 的 `assets.directory` 也指向它的 `dist`。迁移第 38 条追平之前不能删。
- **迁移第 38 条时整包删除**（见 `docs/正式版架构.md` 第 8 节）。

## 规则和数据用自己那份快照

`src/core-snapshot/` 是**迁移第 12 条动手之前** `packages/core/src` 的整份拷贝：
规则引擎、类型、18 张 AI 牌、24 张技能牌、7 位英雄、题库、预生成答案表。
`tsconfig.json` 的 `paths` 和 `vite.config.ts` 的 `resolve.alias` 各有一条
`@ai-duel/core` → `./src/core-snapshot/index.ts`，所以这个包的源码里那 67 处
`from '@ai-duel/core'` 一个字都不用改，`package.json` 里也不再依赖那个包。

**为什么要拷一份**：正式版的 core 从第 12 条起做破坏性改动——卡牌数据搬去 `content`，
`createGame` 要多收一份内容目录（`catalog`），后面还会继续改。
而这一版还在线上跑，不该跟着改，也不值得为它维护一层兼容。拷一份是最省事的冻结方式：
它从此和新 core 彻底脱钩，那边怎么改都影响不到线上。
代价是同一份规则在仓库里有两份，但两份里有一份是死的，不会有人去改它。

**别改这个目录**。要改就说明这一版又在加功能了，那不符合上面第一条。
第 38 条删掉这个包时快照一起删。

## 它现在的用处：新客户端的行为规格

正式版是重写不是迁移，但**手感要一比一复刻**。动画时长、缓动曲线、各步之间的等待、
一个事件里多个动作的先后顺序，全部从这里的代码抄，不要凭感觉重新拍数字。
对应的界面说明见 `docs/architecture.md`（同样已冻结）。

抄的时候只抄「什么时候发生、持续多久、按什么顺序」，不要抄实现——
DOM 元素、CSS 类名、GSAP Flip 这些在正式版里都不存在了。
